# Session and View lifecycle checkpoint

2026-10-07. Stage C starts from `9bc7c41`; the earlier `e86ee87` Unity results are historical baseline evidence, not results for this change. Host/HUD fix checkpoint: `fa706a4`; renderer/test checkpoint: `7c5e821`. No authoritative table, resource, content, entity-handle or raw snapshot layout changes are included.

## Confirmed failures and narrow fixes

The [retained red assertions](SessionViewLifecycleRed-20261007.json) record 17 failing cases before the relevant fixes (12 actual adapter cases and 5 host/HUD cases). They establish several distinct defects rather than 16 separate mechanisms:

- Failed Host replacement exposed its already-disposed prior Session and left its tick launcher enabled. Destruction also kept publishing a Session if its cleanup threw. Unpublish and disable/detach first; propagate the cleanup/creation error; only publish successfully created Sessions.
- A disabled HUD's public Build/Refresh could make its controls visible again. Its playing gate now includes `isActiveAndEnabled`; existing multi-pointer cancel and focus/pause ownership remain unchanged.
- Brawler and saved-clock Survivor Guard left pre-restore one-shot effects visible after same-tick restore. A small borrowed-owner `ViewTimelineStamp` compares Session identity, TimelineRevision and LevelVersion and invalidates private transient caches. It does not import SimSession into the shared Presentation assembly, validate registry identities, or serialize anything.
- Both renderers kept their camera callback after disable and kept private resources after Host removal. Disable now clears transient state, detaches its owned camera callback and retains warmed private buffers. Re-enable adopts the weapon cue head; unbind/destroy releases private resources idempotently. A replacement callback belonging to someone else is preserved.
- Survivor's order-400 camera callback could read disposed World resources before its order-500 renderer unbound. It now guards the disposed Session too; a camera-first regression reproduces the direct-dispose case.
- A retained Release from an already completed staff action was blocked because Idle has Phase=0 but retains ActionPulse. Release interpolation gating now applies to running Windup/Active/Recovery phases, excluding Idle/Equipping. Event origin/content and bounded queue order remain authoritative. Skipped-frame backlog still works; disabled time deliberately does not replay weapon bursts.

An initial nonweapon Survivor fixture used Classic's unsaved RunTicks, which resets during restore and already triggered the old rewind check. The final red fixture uses the real Guard snapshot extension so the run counter and Session tick both remain unchanged. No Classic snapshot field was added. An initial Brawler cue fixture missed all targets with a melee weapon and emitted no release; the final fixture uses an actual staff release. Neither initial fixture outcome was treated as a product defect.
