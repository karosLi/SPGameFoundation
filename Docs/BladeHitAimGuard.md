# 刀受击时身体与锁定瞄准分离（2026-10-08）

基线为本地 `1f46b24a51906cb85947bf9b36cd5c26dfd5b0c9`；新反例来自发布 `3c45520` 的实际 `grounded-belt-live` 两档像素。只修已装备 `Slash / 1001` 刀的表现朝向归属。已接受剑刺、权威输入/瞄准/阶段/命中几何、刀的接触前刹停与接触后恢复曲线不改。

## 实际反例与红测试

GPU f116–123、fallback f115–121 受击期间，身体 Facing=+1，武器锁定 aim≈(-1,0)，Hit≈1；刀柄仍贴手，刀却整体朝腿边下指。GPU f121 与 fallback f120 的原图和忠实局部放大保留在 `integration-validation/resume-20261008/blade-turn-review-3c45520/`。`hit-turn-before-during-after-both-tiers-3x.png`、两档连续条带和 `hit-turn-trace-excerpt.csv` 是未修改的失败证据。原始普通录像帧为 JPEG95。CSV 没有世界刀尖，不能把下面的本地 FK 数值称为原生测量。

`BwRenderer` 在 Hit/KO 把武器表现 Stage/Phase 设为 Idle/0，保留运行时瞄准，同时身体继续采用受击后的 Fighter.Facing。这是合法的身体/武器方向分离。旧表现有两个错误假设：

- 刀 guard 直接消费身体 `Turn`，因此身体转右会把仍朝左的刀 guard 旋向下侧。
- 折叠主臂的 incoming reference、近垂直瞄准退胸和肩部空间修正，都隐含身体与新武器方向一致。仅改 guard 角度仍不足以保持最终骨骼连续。

独立新增 `BladeHitAimGuardTests`，不修改恢复精度测试。冻结基线程序集上 **9/9 为红**：包括公开 `WeaponRuntime.View` 左侧锁定瞄准配右向 Hit、记录的 GPU f113–126 根/速度/状态/朝向输入窗口、30/60/120 Hz 与不规则步长中的转身第1/2/4/7 Tick受击取消和完整重入尾段。记录窗口是输入序列重放，不重建未记录的中间渲染步，不声称与原生像素逐点相同。

基线记录窗口重放的最低刀向 Y=-0.993839，最低刃尖模型高度0.280442。最初局部修正另暴露120 Hz第2 Tick取消反例：手速21.5108>15，最终肩X在身体镜像边界跳变约0.168世界单位。局部骨骼探针进一步定位到近垂直aim退胸偏移仍随身体翻面；该失败及诊断保留，未放宽阈值。

## 有界修正

- 新 `WeaponTurn` 使用现有 `turnResponse=1-exp(-15*dt)`，目标取已接纳的武器瞄准方向。身体 `Turn` 保留原职责；没有新振荡器、阶段时间线或角度限幅。
- 刀 guard 与主臂折叠归属采用武器方向。折叠参考显式转换到当前身体模型坐标，身体与锁定瞄准相反时仍保持同一世界手目标。
- 既有退胸、折叠肩距与肩滑统一使用该 incoming-aim 参考，防止仅身体镜像时把其世界偏移翻到另一侧。身体与瞄准一致时转换因子为1，原输入与数值路径保持。
- 腕仍限制在±0.85 rad；刀位置/角度仍由最终 Hand FK 决定；两段真实手臂长度不变。原动作曲线、canonical contact 和权威运行时均未改。
- 每个预分配 `GameplayCharacterMotion` 容量槽增加一个float字段，字段数据为4字节，按Presenter.Capacity保留，不随当前可见实体数分配。此.NET运行时的`Unsafe.SizeOf`实测512→516字节；字段大小和.NET测量不等于原生结构对齐后的stride，Unity/Burst/IL2CPP实际布局须在相应运行时确认。没有新数组、池、逐帧托管分配或第二次IK求解。
