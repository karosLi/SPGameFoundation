# 用 RPG 小游戏验证基座

为了检验 SinglePlayerFoundation 是否真的与玩法无关，在贪吃蛇之外做了第二个玩法：一个俯视角动作 RPG 地牢（`Assets/RpgFoundation`）。
本文记录它用到了基座的哪些部分、为此补充了什么，以及还缺什么。

## 玩法概要

- **地牢**：房间 + 走廊，按（存档种子, 层数）确定性生成。楼梯放在离起点步行距离最远的房间，每 3 层出一个 Boss（Warden）把守楼梯，第 9 层通关。
- **英雄**：摇杆移动；按住攻击，近战扇形，自动瞄准最近的敌人；火球技能；药水。升级提升基础属性；武器 / 护甲以永久修正（modifier）的形式生效。
- **怪物**：史莱姆（近战）、骷髅弓手（远程，保持距离）、蛮兵（坦克）、Boss。
  - AI 是一个 Burst 并行 Job：闲逛 → 视野内 + 仇恨范围触发追击 → 在流场上绕墙走 → 进入射程攻击 → 丢失视野 4 秒后回家。被打会强制仇恨。
- **奖励**：经验 / 等级、按权重掉落（金币、药水、装备）、拾取、背包换装。
- **流程**：菜单（新游戏 / 继续）→ 游戏 → 清层（下楼）/ 死亡（重试本层）/ 通关。每层开始自动存档。
- **由四个模块组合而成**（贪吃蛇是单模块）：Core（配置、状态、事件）、Dungeon（地图、流场、楼层流程、楼梯）、Actors（英雄 / 怪物、移动、AI、网格、战斗、结算）、Rewards（掉落、经验、拾取、背包）。

## 基座原样复用的部分（验证通过）

| 基座能力 | RPG 中的用法 |
| --- | --- |
| SoA 表 / 列、EntityRegistry、销毁队列（排序回放） | 角色 / 投射物 / 掉落物三张表；死亡和投射物命中都走销毁队列 |
| TickPipeline 访问声明 + 依赖追踪 + 每 tick 单次同步 | 13 个系统、10 个阶段；AI、移动、网格、战斗都是 Burst Job |
| SpatialGrid（计数排序） | 角色网格同时供挤开（separation）、近战扇形、投射物扫掠使用 |
| ParallelQueue / EventQueue | 命中、投射物请求、死亡、表现反馈 |
| SimRandom | 伤害浮动 / 暴击、掉落、闲逛点。确定性已验证：机器人两次跑完全一致，且 harness 会打乱并行执行顺序 |
| SimSession / SessionHost（固定步长、插值、渲染重叠） | 原样使用 |
| ModeDefinition 多模块组合 | 4 个模块，通过 RpgKeys 共享 key；也暴露出模块间有隐式依赖（见下文“仍缺”） |
| CircleBatch（GPU 驱动档 / GLES3 数据纹理档） | 角色、眼睛、掉落物、投射物、光晕；两档都在 PlayMode 中跑过并截图 |
| PerfHud、dotnet harness、CI 截图发布 | 原样使用 |

## 为 RPG 补进基座的部分（通用，已有测试）

1. **SPF.Shell（新程序集）**：原来 UI 控件、输入、相机都写死在 SnakeFoundation 里。现在抽出：
   - `UIFactory`（新增血条 / 进度条）、`VirtualJoystick`、`HoldButton` / `TapButton`、`FloatingTextPool`（伤害数字）；
   - 通用输入 `InputFrame` / `IInputSource` / `InputRouter`（键盘、触屏、脚本三种来源），一次性按键会锁存到 tick 消费为止；
   - `FollowCamera2D`。
   - 贪吃蛇已改用这些控件，由 `SnakeTouchInput` 适配到它自己的指令。
2. **`InputFrame` 放进 Contracts**，模拟层可以直接存放通用输入。
3. **静态关卡几何**：`TileMap` / `TileMapView`。
   - 圆与瓦片碰撞：推出、沿墙滑动、子步防穿透；
   - 视线检测：网格遍历（Amanatides–Woo）。
4. **寻路**：`FlowField`，Burst BFS 距离场 + O(1) 方向查询（不切角）。所有追同一目标的怪物共用一张场。
5. **通用属性与修正**：`StatBlock`（8 个由游戏定义的属性）+ `ModifierSet`（8 槽，加 / 乘，限时 / 永久，按来源刷新）。原来的 `BuffSet` 写死了贪吃蛇的属性。
6. **战斗规则**：`Health`、`CombatMath`（护甲减伤、浮动 / 暴击、扇形判定）、`Cooldown`。
7. **成长与掉落**：`LevelCurve`、`LootTable`（加权、确定性）。
8. **存档**：`ProfileStore`。带版本号和 FNV 校验，先写临时文件再替换（原子），损坏或版本更新的文件会被拒绝而不是读一半。
9. **表现层**：`QuadBatch`（CPU 四边形，覆盖层或带深度两种）+ `SPF/VertexColor` 着色器。原来只能画圆盘和链条，画不了瓦片地图和血条。
10. **测试支撑**：`UIDriver` 移到 `SPF.Testing`，两个游戏共用。
11. **GPU 帧时间**：`GpuFrameTimer` + A/B 基准，可以打包到真机运行。

## 仍缺 / 建议（按影响排序）

1. **精灵 / 动画渲染**：只有圆盘和纯色四边形，没有图集 UV、帧动画、朝向翻转、九宫格。正式的 RPG 首先缺这个。建议做一个按图集实例化的 SpriteBatch，两档都支持。
2. **关卡 / 场景生命周期**：楼层切换靠 FloorSystem 手动清表、重建地图。哪些数据跨层保留（Profile）全靠约定。建议基座提供关卡作用域：资源标注为会话级或关卡级，统一清理和重建。
3. **主线程系统的访问声明**（已部分修复）：结构性修改的系统（结算、拾取、楼层）都声明为空，即“屏障”系统。
   - 真机 Unity 测试暴露了一个真实 bug：管线只把之前所有工作的句柄传给屏障系统，却没有完成它。RPG 的结算系统在主线程读命中队列时，战斗 Job 还在写，被 Unity 安全系统拦下。
   - .NET harness 同步执行 Job，抓不到这类问题。
   - 现在管线会在调用屏障系统前先完成依赖。
   - 仍建议增加显式的 `MainThread()` 声明，并在调试模式下检查越权访问。
4. **表现事件的投递语义**：反馈事件按约定由渲染器读取后清空；无头运行时队列会溢出丢弃。建议基座提供有明确消费者语义的表现事件通道。
5. **定义数据库**：怪物 / 装备 / 掉落表是每个游戏各写一遍“ScriptableObject → 烘焙成 NativeArray”。建议提供通用的定义表资产 + ID 注册（编辑器校验、热重载）。
6. **存档范围**：只存 Profile，不能中途存档（需要把表 / 资源序列化成快照）。回放和存档可以共用这套快照。
7. **导航**：流场只适合共享目标；缺少每个代理的 A*（多目标）、动态障碍、怪物之间的避让（目前只是软挤开）。
8. **物理反馈**：没有击退 / 冲量，碰撞形状只有圆。
9. **UI**：只能用代码搭建 UGUI；没有数据绑定、列表虚拟化、本地化、主题。背包是手写的。
10. **贪吃蛇尚未完全迁移**：它仍使用自己的 InputRouter / PlayerCommand、相机和 BuffSet。属于清理工作，不影响功能。

## 测试与基准

- **EditMode（RPG 11 个）**：
  - 地牢连通且确定性；
  - 新游戏生成楼层；
  - 怪物追击并攻击；
  - 击杀给经验和掉落；
  - 火球远程命中、被墙阻挡；
  - 换装与药水；
  - 楼梯 → 下楼保留进度；
  - 死亡 → 重试恢复层首；
  - 存档 → 继续得到同一张地图；
  - 机器人两次运行完全一致；
  - 机器人连清两层。
- **基座新增 6 个测试**：瓦片碰撞 / 视线、流场全图可达、修正叠加与过期、战斗数学、成长与掉落、存档往返与损坏拒绝。
- **PlayMode**：
  - UI 自动化：新游戏、摇杆、攻击按钮击杀并出现伤害数字、背包换装、楼梯下楼后从存档继续、死亡重试；
  - 两个渲染档各让机器人玩 12 秒并截图（`ci-screenshots` 分支上的 `rpg-gpu.png` / `rpg-datatex.png`）。
- **`HordeBenchmark`**：约 370 只怪物的大地图，机器人在玩，结果写入 `perf-rpg.txt`。
  - M5 Pro + Burst 实测：tick 均值 0.106 ms（p95 0.155 ms）。
  - 分系统：战斗 0.020、移动 0.020、AI 0.018、角色网格 0.015、流场 0.008 ms。
  - 主线程调度耗时等于整个 tick（0.106 ms），同步等待为 0：结算阶段是主线程屏障，要等前面所有 Job 完成，所以 RPG 的 tick 拿不到渲染重叠。想重新获得重叠，需要把结算改成 Job（命中排序 + 应用），或者把屏障推迟到下一 tick 开头。这一点也是上面第 3 条的延伸。
