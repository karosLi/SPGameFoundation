# Blade controlled recovery and closed grip

This design starts at local `f46c7651193186126bcaa9f3f6537002293b7e2c` (same tree as published `178d268de5e44783461f20c75324f2a3de503439`). The scope is blade presentation only. No new hitstop or outcome inference is introduced.

## Diagnosis from actual frames

The d2cc1f9 GPU contact sequence f045–047 (1.999–2.099 s) changes forearm angle from +11.4° to +2.2°, blade direction from −7.0° to −33.4°, and wrist flexion from −18.4° to −35.6°. About 17° of the remaining 26° cut is wrist motion after the forearm nearly levels. The hand still advances 0.039 and drops 0.043 model units; chest angles −8.3°, −8.7°, −7.9° do not support an early-retraction or torso-snap diagnosis. Held-attack f005–009 supplies an unobstructed corroborating view. The weapon primary pivot at art pixel (46,48) remains fixed. A pelvis tile shrunk to a 0.19-square hand has no closed-finger silhouette and makes the joint read as a narrow connector.

Evidence lives in `integration-validation/resume-20261008/blade-grip-followthrough-review-d2cc1f9/` (FINDINGS.md, contact-followthrough-trace.csv and native-pixel crops), plus `blade-sword-review-d2cc1f9/` and the restored native-d2cc1f9 source recordings. ## Source principles and applicability

- [Muriel Cartwright, GDC 2014 Animation Bootcamp](https://media.gdcvault.com/GDC2014/Presentations/Cartwright_Muriel_Animation_Bootcamp_Fluid.pdf), pp. 6–13, 20–24, 26, 28–34: readable key poses, varied timing, follow-through and gameplay constraints. Applicable here as a few coordinated keys; the talk does not prescribe our timing constants or certify this rig.
- [Disney Animation: Animation](https://www.disneyanimation.com/process/animation/): communicate performance through posing and timing. Applicable to whole-character intent and readable grip, not a mandate for a particular engine or asset.
- [Microsoft animation principles](https://learn.microsoft.com/en-us/windows/win32/lwef/animation-principles): anticipation, acceleration/deceleration, arcs and overlapping follow-through. Applicable to purposeful braking without a sudden freeze; this legacy document is general animation guidance.
- [Unity Two Bone IK](https://docs.unity3d.com/Packages/com.unity.animation.rigging@1.2/manual/constraints/TwoBoneIKConstraint.html): target position/orientation and a coherent bend hint are separate responsibilities. Keep the existing analytic two-bone solve and bend side; install no package.
- [Unity Rigging Workflow](https://docs.unity3d.com/Packages/com.unity.animation.rigging@1.2/manual/RiggingWorkflow.html): ordered constraint evaluation matters. Keep body composition → arm IK → palm orientation → final FK/attachment order.

## Planned correction

Keep the loaded overhead pose and exact existing contact position, orientation and first derivative. From contact, author a shared braking interval for grip, blade and torso into a compact settled key, then recover to the existing guard. Initial experiments use the existing active interval to fit roughly 33–67 ms of settling and 10–20° of extra blade sweep. Those ranges are hypotheses, not official values or acceptance gates. Avoid a separate weapon low-pass, a rigidly locked wrist, global amplitude inflation or many overlapping oscillations. The forearm must still carry meaningful motion; measure final FK wrist/forearm/blade change and timing, not merely authored values. Preserve C1 contact and recovery continuity, reasonable grip articulation and the old ground-clearance controls.

Use one new original closed-grip tile per existing character color scheme, selected only for slash with the blade visual. The blade palm must visibly overlap the existing hilt at the unchanged primary pivot. Keep all old atlas entries and UV placement unchanged by appending the tiles after the existing entries; inspect actual packing dimensions and edge extrusion. Replace the existing hand instance in the fixed batch, adding no per-actor instance/draw call or per-frame allocation. Do not repurpose the new tile for the accepted sword.

The view contract does not currently provide a pose-safe authoritative hit result. This pass uses the same controlled trajectory for hit and miss. No phase-to-hit inference or new hit/miss branch is authorized.

## Results

The bounded patch is implemented and locally checked. Fresh native capture and user acceptance remain pending as detailed below.

### Measured implementation choice

The final trajectory keeps the entire incoming slash curve through exact contact. Its shared settle key is 45% of the existing contact-to-active-end interval: 67.5 ms for the default 60 Hz weapon profile, 75 ms for the tick-rounded 30 Hz profile. These are fitted presentation timings, not changes to either authoritative marker. Grip X, blade angle and chest finish derive from the incoming Hermite tangent; the grip Y terminal displacement carries twice the constant-deceleration displacement, so the elbow/forearm carries the remaining cut. This is one local terminal-key adjustment, not an increase to the overhead attack amplitude. The vertical hand speed can build briefly after contact before braking; all authored grip/angle/body derivatives reach zero at the same settle key, followed by C1 recovery to the original guard. Existing two-bone bend direction and rigid blade-to-palm attachment are retained.

The first experiment only shortened the independent channels. It reduced sweep from about 34° to 14.5°, but still left 11° at the wrist versus 3.6° at the forearm. It was rejected by the new control and is retained in `motion-first.log`. The fitted lower hand key passes across 72 combinations: blade sweep 14.36–15.15°, maximum incremental wrist flexion 4.06–5.67°, and forearm contribution at the terminal blade pose 9.66–13.19°. The old full-blade clearance control reports a minimum 0.857 model units. The forearm carries most of the remaining cut. No test threshold was relaxed to accept it.

### Original art and resource bound

Two original supersampled 40×32 grip tiles replace the existing hand instance only when an equipped slash resolves to blade visual 1001. Four curled fingers and a diagonal thumb cover the unchanged hilt pivot. Both palettes match the existing roles. Each tile contains 406 fully opaque and 56 partially transparent texels, with a transparent border. The final quad is 0.24×0.192 model units; its visible alpha bounds are 0.174×0.120 including the cuff, versus the former pelvis-hand bounds 0.1425×0.114792. Most additional width is the cuff; the closed palm itself is about 0.132 wide. This avoids disguising the issue with an oversized fist. Source-art composition is diagnostic only; actual gameplay pixel readability is pending native capture.

The atlas sorts frames by height, so simply appending a small tile would move old white/disc frames. `SpriteAtlasBuilder.Build` now offers an optional sorted-prefix count. Its default/full-prefix path uses the exact previous sorting overload; this caller freezes its previous 24-entry sorted prefix and packs the two added tiles afterward. Original origins, UVs, dimensions, 16 body-tile RGBA hashes and all four weapon-tile RGBA hashes match baseline. Classic atlas remains 1024×256 RGBA32 (1,048,576 bytes); weapon atlas remains 1024×512 (2,097,152 bytes): **zero added GPU texture bytes**. The tiles add 10,240 bytes of authored RGBA content inside previously unused atlas area. The existing native UV cache grows by two float4 values (32 bytes) at construction; two small managed frame IDs add 8 payload bytes plus their array overhead, plus two atlas frame/origin records. Source tile generation is loading-time work. The 32-byte figure is only the added persistent native UV cache; it excludes the two frame records, managed grip-frame array and loading-time PixelCanvas/packing allocations. Those cold-path bytes have not been claimed as a measured total. There are still 19 instances / 608 useful packed bytes per equipped actor and no new draw call, per-actor renderer, hot-path allocation or new package.
