# Survivor guard and annular-skill slice

## Reference and scope

Reference 4 visibly contains outlined, non-pixel characters, individual enemy health bars, hit flashes, two electric rings and a structure with a health bar. A still image does not establish the original game's objective, targeting rules, timing or win condition. This implementation is an **original protect-the-beacon example** using those visible presentation needs. It does not copy the reference's characters, UI, branding or assets.

## Run it

- Unity 2022.3: **SPF → Survivor → Create Guard Example Scene**, then Play.
- Or use `SvGameBootstrap.CreateGuardExample()` in a harness/scene.
- Or add `SvGameBootstrap` and enable `Guard Example` in the Inspector. A custom config takes precedence; select its variant/settings explicitly.
- Classic `SvConfig.CreateDefault()` and `SvGameBootstrap.Create()` still default to classic rules and point-filtered pixel art.
- `SvConfig.CreateGuardExample()` supplies the guard rules; `SvArtStyle.SmoothOutline` independently selects presentation. Both render tiers consume the same simulation.

Move with WASD or the touch joystick. Intercept enemies near the beacon, collect gems, and choose upgrades. The original example spawns for 90 seconds at 30 Hz, then requires all surviving enemies to be defeated. Losing either the hero or beacon ends the run. Restart resets pools, objective health, loss reason and ring cadence. Menu is available during play and after either outcome.

## Runtime reuse

No second combat simulation, physics world, per-enemy GameObject, Collider or Canvas was added. The guard variant extends `SvModule`, the existing SoA enemies, pooled bullets/gems, two-level spatial grid, job pipeline, damage queues, resolver, destruction/reward path and snapshot resource.

`SvAnnularSkill` is independently usable in classic or guard configs. Two continuous visual bands deal damage once every `TickInterval` playing simulation ticks. Defaults: radii 2.4/5.4, half-width 0.24, six ticks, 38 DPS. Pulse damage is DPS × fixed tick seconds × interval × Might. Hollow centers do not damage. A band with radius zero or less is disabled consistently in simulation and rendering. Overlapping bands contribute one hit per target per pulse. Level-up/menu/terminal screens freeze cadence. Cadence is saved in snapshots and is independent of interpolation, render time and quality.

The annular broadphase queries grid cells expanded by the largest target radius; inclusive `CombatShapes.AnnulusHitsCircle` handles exact inner/outer tangencies. This avoids the grid circle query's strict-edge exclusion. Shooter projectiles compare first swept contact fractions against hero and beacon; the nearest blocker wins (ties favor the solid beacon). Guard enemies pursue the beacon unless the hero is within the configured interception radius. Contact pushes enemies outside the solid beacon and applies the strongest pending hit at the configured tick cooldown. The finite wave deadline stops further spawns; victory waits for actual removal of remaining enemies. Lethal queued damage takes priority over victory.

## Snapshot compatibility

Classic mode with annular skills disabled preserves the complete 97a2b34 snapshot payload and world resource order. The old float damage queue is retained; explicit sign-tag helpers represent hero damage as positive and beacon damage as negative, with negative entries consumed only by guard rules. No extra saved world resource is inserted. New fields append a magic/version-tagged extension after the original command queue only when guard or annular rules are enabled at module construction. As with other world snapshots, restore requires the same config/layout; changing the enabled rules is not an implicit migration.

`SvLegacySnapshotFixtures` contains a fixed compressed checkpoint and continuation captured by an isolated console process loading the baseline Survivor assemblies. Baseline Survivor runtime sources were byte-compared to git 97a2b34 before capture. The regression restores and immediately rewrites the old snapshot byte-for-byte, including enemies, bullet, gems, queued hits/damage and a pending command. The .NET backend also compares the 23-tick continuation to bytes generated by the old assembly; real Unity checks semantic continuation because Burst fast-math can differ from harness floating-point results.

## Rendering and visual budgets

Original procedural outlined cutouts are rasterized at 3× resolution, downsampled with alpha-aware coverage, and packed with bilinear filtering, padding and edge extrusion. Smooth actors use a translucent sprite batch, not opaque alpha clipping. Enemies, hero, beacon and gems are culled/packed first, then ordered back-to-front by depth using a Burst, native-array **stable merge sort, O(N log N)** with persistent scratch storage. Equal-depth ties retain insertion order. Both GPU-driven and data-texture tiers receive the same ordered packed instances. This is sprite instancing, not a new skeletal BAT/GPU animation backend.

Enemy health bars and blob shadows are filled into batched native sprite slots alongside the existing Burst draw job. Hero/beacon shadows use the shared `BlobShadow` helper; their bars use the same bar batch. No world-space canvases are instantiated per actor. Hit flashes retain the shared packed flash channel plus a cyan tint. The ordinary bolt has a short elongated glow, not a falsely claimed continuous damaging beam. Electric ring strokes track the configured damage bands; their small visual jitter stays within band width.

`FrameGovernor.LevelChanged` affects only visual budgets: enemy shadow counts 768/256/128/32, active death-effect admission 400/192/96/48, and ring segments 64/64/32/32. Both bands and all health bars remain visible. Simulation parameters, actor capacity, cadence, damage and targeting never change with quality. All native sprite buffers and sort scratch are allocated at bind, with batch pages warmed before play.
